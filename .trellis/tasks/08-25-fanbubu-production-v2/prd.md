# 饭卜卜生产增强版：身份资料、多样化、可靠天气与 AI 用餐意图

## Goal

在不破坏现有 CloudBase 私有登录、HTTP 数据网关和已上线小程序主流程的前提下，完成四项可独立验收但必须一体发布的增强：微信身份登录后可跳过地完善头像昵称；结构化轻菜谱由 60 道扩充到 120 道；推荐结果因用户与历史而产生可靠差异；天气改为国内主源、国际备用源和缓存三级降级；首页增加自然语言“用餐意图”助手，但 AI 只负责理解输入，最终候选、安全过滤、营养与持久化仍由 FastAPI 规则服务负责。

### 1. 微信登录与可跳过资料完善

- 微信主登录继续使用 `wx.cloud.callContainer -> POST /api/v1/auth/cloud-login`；FastAPI 校验 CloudBase 注入的 `X-WX-OPENID`、`X-WX-APPID`、`X-WX-ENV`，创建/读取用户并签发项目 JWT。
- “身份认证完成”以获得可信 openid 对应的内部 user id 和有效业务 JWT 为准，不把头像、昵称是否填写当作登录成功条件。
- 不尝试静默读取微信头像昵称。首次登录后，若仍是默认昵称或无头像，显示一次可跳过的资料完善界面：昵称使用小程序原生 nickname 输入，头像使用 chooseAvatar，经用户明确操作后上传 CloudBase 云存储。
- 跳过只关闭当前设备的一次引导，不清 JWT、不降级为游客；“我的”页面保留再次编辑入口。
- 游客登录不出现微信资料完善提示；微信用户与游客身份不得自动合并。
- 后端提供鉴权后的公开资料更新接口，仅允许修改经过清理和长度校验的 nickname 与 `cloud://`/`https://` avatar 地址，并返回更新后的用户摘要。

### 2. 120 道可靠轻菜谱与个性化多样性

- `recipe_seed.json` 最终恰好 120 条，角色目标为主菜 50、蔬菜 50、主食 20；每条关联一个现有且唯一的 Food。
- 全部 120 条必须有 4–6 个可执行步骤、量化关键食材、份数、准备/烹饪时长、每份估算营养、营养依据和版本；肉蛋水产必须包含明确熟制动作，不写治疗或保证减脂等医疗化表述。
- 新增菜谱步骤必须独立改写，不整段复制第三方内容；`source_url` 如填写则必须为 HTTPS 且可追溯，未填写时必须有明确的营养估算依据。
- 构建时执行严格数据校验，阻止数量、角色、重复、食材、步骤、营养、来源格式或基本熟制安全不合格的数据进入种子。
- 推荐器保留现有硬过滤、营养和节气权重，在此基础上使用近 7 日选择/曝光、收藏偏好和用户稳定种子做有界探索：只在高质量分数带内改变次序，不能为了“看起来随机”选明显更差的菜。
- 同一 `request_id` 必须幂等；换一套使用新 `request_id`，候选充足时至少更换 `ceil(N*60%)` 个菜；不同用户在相同输入下不再被固定 food id 排序锁成同一套餐。

### 3. 天气链路

- 国内主源采用 QWeather 当前天气 API，直接用经纬度查询；Cloud Run 环境变量使用 `QWEATHER_API_HOST` 与 `QWEATHER_API_KEY`，二者必须同时配置或同时缺省。
- 高德 Web 服务作为低频备用源：先逆地理编码取得 adcode，再查询天气；`AMAP_WEB_SERVICE_KEY` 只存服务端。Open-Meteo 退出生产默认调用链，仅保留可选诊断开关。
- 三方客户端均设短连接/总超时和结构化日志，不输出凭据与完整坐标。服务端缓存最近成功天气：1 小时新鲜缓存、最多 12 小时陈旧兜底；新鲜缓存命中时不访问外部网络，QWeather 失败后才尝试高德，两者失败后返回陈旧真实快照，最后才返回中性天气。
- WeatherData 以兼容方式增加 `source`、`is_stale`、`observed_at`；前端区分实时、缓存和不可用，不把中性降级缓存成真实天气。
- 用户拒绝定位或未授权时继续支持手动城市/无天气推荐；高德逆地理编码仅作为天气兜底的服务端内部步骤，不接入地图商户数据，也不在主源成功时产生调用。

### 4. AI 用餐意图助手

- 首版不是通用聊天机器人，而是首页一个紧凑输入框，把“冰箱有番茄鸡蛋、20 分钟、少油”等自然语言解析成受控 `MealIntent`。
- 小程序通过 `wx.cloud.extend.AI.createModel("cloudbase")` 调用已在 CloudBase 控制台开启的模型；前端不得持有外部大模型 API Key。
- 在写入实际模型调用前，必须先验证当前环境的小程序成长计划/Token 额度、模型组和具体模型可用；不可用时功能开关保持关闭，基础推荐照常工作。
- AI 输出只接受严格 JSON：已有食材、排除食材、最长用时、目标、自己做/外食偏好和一句摘要。解析失败、超时或字段越界时不提交错误约束。
- 后端重新校验 MealIntent，将排除食材作为硬过滤，将已有食材、时间和目标作为有界软加分；AI 不直接生成 food id、营养值、菜谱、诊断或数据库写入。

## Acceptance Criteria

- [ ] 微信一键登录在模拟器和真机均获得可信用户 id 与可用 JWT；重启小程序后会话可恢复，且不依赖 `WX_SECRET`/code2session。
- [ ] 默认微信用户会看到一次资料完善入口；选择头像、填写昵称并保存后，“我的”页即时更新，重新登录仍保留；跳过后仍可使用所有功能。
- [ ] 非法昵称、超长值和不允许的头像 scheme 被后端拒绝；任一用户不能修改其他用户资料。
- [ ] `recipe_seed.json` 恰好 120 条且角色为 50/50/20，严格校验器、幂等导入和菜谱 API 测试全部通过。
- [ ] 120 道菜的关键食材、步骤、时间和营养均通过自动校验；新增 60 道附人工审阅清单，随机抽查不少于 20 道可按步骤完成。
- [ ] 同一 `request_id` 响应幂等；同用户连续换一套满足 60% 更新规则；不同用户相同上下文的结果不再被固定 id 全部锁死；硬忌口测试始终通过。
- [ ] QWeather 成功、QWeather 超时后高德成功、双源失败后陈旧缓存、完全无缓存时中性降级四条路径均有测试；Open-Meteo 默认未被调用。
- [ ] 真机授权定位后天气可显示来源/缓存状态；拒绝定位或天气失败时推荐仍在可接受时限内返回。
- [ ] AI 预检通过时可把自然语言解析成 MealIntent 并影响推荐；预检未通过、AI 超时或 JSON 非法时基础推荐无回归。
- [ ] 后端 pytest/Ruff/mypy、前端 Vitest/ESLint/vue-tsc、H5 与 mp-weixin 构建、Docker `/health` 烟测全部通过。
- [ ] 微信开发者工具模拟器、预览和至少一台真机完成登录、完善/跳过资料、获取/拒绝天气、连续换餐、菜谱详情、收藏与 AI 降级验收。

## Out of Scope

- 静默获取微信昵称头像、手机号或通讯录。
- 自动合并游客与微信账户、家庭成员独立账号。
- AI 通用问答、医疗诊断、自动生成营养数值或未经校验的菜谱。
- 外卖平台、地图店铺、实时价格和下单 API。
- 为了天气引入 VPC/NAT、固定公网出口 IP 或新的付费服务器。
